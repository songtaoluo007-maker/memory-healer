## 1. 决策摘要

《拾忆》的语音系统采用“关键剧情预生成 + AI 自由对话实时生成”的混合模式：

- 关键旁白、固定剧情对白、记忆碎片独白、假说复原和结局独白使用本地 AI 模型提前生成并人工审核。
- 玩家与 NPC 的自由对话使用同一套角色声音档案实时生成。
- 主生成引擎采用 CosyVoice 3；现有 Edge TTS 保留为运行时降级引擎。
- 全部人物使用模型原生 AI 声线，不采集、克隆或模仿真人声音。
- 每个角色拥有稳定的声音血缘、年龄变体、情绪边界和固定生成参数，不能在不同台词间随机换声。
- 语音故障永远只关闭声音，不得阻断文字、状态更新或剧情推进。
- 语音系统必须由内容清单驱动，以支持后续剧情和玩法大幅扩充，而不增加新的硬编码入口。

## 2. 目标

### 2.1 产品目标

1. 让人物在五个时代中具有可辨识、可延续的声音身份。
2. 让关键剧情具备接近影视对白的停顿、情绪和空间感。
3. 保留 AI 自由对话的开放性，同时避免音色漂移和长时间等待。
4. 让新增剧情能够通过内容配置接入语音，不要求逐场修改前端或 API。
5. 在免费软件方案下完成本地制作，并为未来部署成本保留清晰边界。

### 2.2 技术目标

1. 将角色声音定义、生成供应商、缓存和播放解耦。
2. 固定剧情音频可重复生成、可审核、可追溯。
3. 动态语音具有超时、缓存、熔断和可玩的静音降级。
4. 字幕、对白文本和音频使用同一个稳定台词 ID。
5. 所有声音状态可测试，不依赖人工点击才能发现严重错误。

## 3. 非目标

- 本阶段不扩写主线、支线或人物关系；剧情容量和核心玩法扩充另立设计。
- 不实现真人配音录制、真人声音克隆或名人音色模仿。
- 不为按钮、热点、背包说明和普通界面文字配音。
- 不在首版实现逐字卡拉 OK 字幕、自动口型或多语言配音。
- 不把本地 GPU 推理能力作为玩家能够通关的前提。

## 4. 当前状态与问题

当前项目已经具备：

- `POST /api/tts/speak` Edge TTS 接口。
- 七个 NPC 配置到不同 Edge TTS 音色、语速和音高。
- NPC 自由对话完成后自动调用前端 `speak()`。
- 文本优先、TTS 失败不阻断剧情的基础降级。
- 文本、音色、语速和音高共同参与的有界磁盘缓存。

当前缺口：

- 固定剧情、旁白、记忆碎片、假说确认和结局没有语音。
- 角色声音只绑定供应商音色名，没有独立的角色声音档案。
- 同一人物不同年龄没有可验证的声音血缘。
- `useAudio.ts` 同时承担 BGM、音效和 TTS，职责过多。
- 没有统一播放队列、抢占规则、字幕时序或 BGM ducking。
- 没有预生成、人工审核、资产版本和批量回归流程。
- 当前角色内容存在年龄线矛盾：2050 年小雨 48 岁，2089 年又被写成 22 岁。

## 5. 语音覆盖范围

### 5.1 必须配音

| 内容类型 | 生成方式 | 是否人工审核 |
| --- | --- | --- |
| 时代进入与离开旁白 | 预生成 | 是 |
| NPC 固定剧情对白 | 预生成 | 是 |
| AI 自由对话回复 | 实时生成 | 抽样 |
| 关键记忆碎片独白 | 预生成 | 是 |
| 假说确认后的真相复原 | 预生成 | 是 |
| 结局独白 | 预生成 | 是 |

### 5.2 不配音

- 按钮、热点名称和普通导航。
- 背包、档案和设置说明。
- 玩家自己的选择项和自由输入文本。
- 非叙事性的成功、错误和加载提示。

### 5.3 极短系统声

“记忆已连接”“因果链成立”等少量关键系统反馈可以使用统一的合成耳语或短声音标识。它们属于氛围层，不能抢占人物对白，也不能承担必要信息。

## 6. AI 声音选角

### 6.1 陈守义声音血缘

所有年龄共用 `voice_lineage_id = chen_shouyi`。

#### 25 岁 · 1972

- 温暖清亮的青年男声，中低音域。
- 语速自然，带轻微西安口音。
- 谈到皮影时音色变亮；忧虑时收住尾音。
- 禁止粗犷、播音腔和夸张方言表演。

#### 43 岁 · 1990

- 保留青年时期的共鸣位置和核心音色。
- 音域略降，声音更厚，句子中的用力感更强。
- 犹豫通过停顿和呼吸表现，不使用反复结巴。
- 禁止让角色听起来像另一名中年演员。

#### 77 岁 · 2024

- 仍能辨识青年时期的音色血缘。
- 增加气息感、慢速和轻微颤音。
- 记忆混乱通过停顿、重复关键词和突然降低音量表现。
- 禁止使用滑稽、刻板或过度虚弱的老人声。

### 6.2 小雨声音血缘

所有年龄共用 `voice_lineage_id = xiaoyu`。

#### 22 岁 · 2024 记忆

- 柔和、清澈，带克制的焦急感。
- 谈到爷爷时允许短暂停顿或哽住。
- 禁止持续哭腔和偶像剧式撒娇音色。

#### 48 岁 · 2050

- 声音稳定、成熟，公开演讲具有力量。
- 提到爷爷时短暂破防，随后恢复控制。
- 禁止纯新闻播音腔或缺少私人情感的演讲声。

#### 87 岁 · 2089

- 缓慢但清晰，温柔而有决定力。
- 保留 48 岁时期的咬字和音色血缘。
- 禁止将其处理成无力、含混或失去主体性的老人声。

### 6.3 站台陌生人 · 1990

- 明亮、外向、语速稍快的青年男声。
- 带轻微湖南口音。
- 商业试探通过语气收紧表现，不能演成油滑反派。

### 6.4 记者 · 2050

- 清晰、克制、有温度的中性偏女声。
- 提问干净，追问时有压力但不咄咄逼人。
- 禁止传统电视新闻播音腔。

### 6.5 记忆旁白

- 与任何人物都不同的低饱和“档案声线”。
- 冷静、稍有距离感，同时保留人性温度。
- 只用于转场、碎片复原和结局，不朗读工具性文字。

## 7. 声音档案模型

角色内容不直接绑定 `CosyVoice`、Edge 音色名或具体模型版本，而是引用稳定档案 ID。

建议数据结构：

```json
{
  "id": "chen_shouyi.age_43",
  "voice_lineage_id": "chen_shouyi",
  "age_stage": 43,
  "provider_profile": {
    "cosyvoice": "chen_shouyi_age_43_v1",
    "edge_fallback": "zh-CN-YunxiNeural"
  },
  "seed": 19721990,
  "register": "warm_mid_low",
  "pace": 0.92,
  "dialect": {
    "name": "xian",
    "strength": 0.18
  },
  "breathiness": 0.12,
  "emotion_limits": {
    "sad": 0.72,
    "hopeful": 0.82,
    "angry": 0.35
  },
  "forbidden_traits": [
    "broadcast_delivery",
    "caricature_dialect",
    "uncontrolled_sobbing"
  ],
  "version": 1
}
```

声音档案必须包含：

- 稳定档案 ID 和声音血缘 ID。
- 年龄层、音域、语速、方言和呼吸参数。
- 情绪强度上限。
- 固定种子或稳定说话人向量。
- 禁止表现。
- 版本号和参考试听台词。

## 8. 台词模型

剧本、字幕和语音共用同一个稳定 `line_id`。

```json
{
  "line_id": "scene_1972.chen.knife_01",
  "speaker_profile": "chen_shouyi.age_25",
  "text": "这把刻刀，是额爷爷留下来的。",
  "emotion": "guarded",
  "intensity": 0.35,
  "space": "xian_alley_small_stage",
  "delivery": "pre_generated",
  "interrupt_policy": "dialogue",
  "version": 1
}
```

必填字段：

- `line_id`
- `speaker_profile`
- `text`
- `emotion`
- `intensity`
- `space`
- `delivery`
- `interrupt_policy`
- `version`

`delivery` 只允许：

- `pre_generated`
- `runtime`
- `silent`

## 9. 系统架构

### 9.1 声音档案层

负责加载和校验角色声音档案、年龄变体、情绪边界和供应商映射。内容注册表在启动时拒绝不存在的档案、声音血缘或非法情绪。

### 9.2 语音编排层

新增独立 `VoiceService`，职责为：

- 校验台词与声音档案。
- 选择预生成资产、CosyVoice 或 Edge TTS。
- 计算确定性缓存键。
- 应用超时、并发、熔断和降级策略。
- 返回音频 URL、供应商、缓存状态、时长和字幕时序。

业务应用服务不直接导入 CosyVoice 或 Edge TTS SDK。

### 9.3 供应商适配层

#### CosyVoiceProvider

- 主要 AI 生成引擎。
- 固定剧情支持离线批量生成。
- 动态对话支持分句或流式生成。
- 运行在独立 Python 环境或容器中。
- 首版使用 Fun-CosyVoice3-0.5B 系列进行试制。

#### EdgeTtsProvider

- 仅作为可选降级。
- 保留现有文本限制、并发限制、原子缓存和容量上限。
- 不作为固定剧情正式资产的唯一来源。

### 9.4 资产与缓存层

固定语音资产由内容哈希寻址。哈希输入至少包含：

- 台词文本和版本。
- 声音档案 ID 和版本。
- 情绪与强度。
- 模型、权重和推理版本。
- 随机种子或说话人向量版本。
- 后处理版本。

正式语音优先提供 Opus，必要时提供 MP3 兼容版本。资源清单记录 URL、编码、时长、响度、文本哈希和生成来源。

### 9.5 前端播放层

将当前 `useAudio.ts` 拆分为：

- `useMusicBus`：BGM 与时代氛围。
- `useSfxBus`：交互与场景音效。
- `useVoicePlayback`：对白队列、抢占、字幕进度和重播。
- `useAudioMixer`：总音量、ducking 和静音策略。

前端只消费统一语音响应和资源清单，不依赖供应商字段决定播放行为。

## 10. 数据流

### 10.1 固定剧情

1. 内容作者提交带 `line_id` 的剧情文本。
2. 内容校验器验证声音档案、情绪和版本。
3. 批处理脚本请求 CosyVoice 生成候选音频。
4. 自动执行格式、时长、响度和空文件检查。
5. 人工试听并批准一个候选版本。
6. 后处理生成正式编码与字幕时序。
7. 资源清单写入内容版本。
8. 前端在进入状态前预取下一句或下一段音频。

### 10.2 AI 自由对话

1. 后端得到最终 NPC 回复和 `npc_mood`。
2. 文本状态立即返回前端，不等待声音。
3. `VoiceService` 使用 NPC 声音档案请求 CosyVoice。
4. 第一段音频可用后开始播放。
5. CosyVoice 超时或不可用时请求 Edge TTS。
6. 两个供应商都失败时返回可识别的静音结果。
7. 前端继续显示文字并允许下一次操作。

## 11. 播放与字幕规则

### 11.1 优先级

```text
结局独白
> 关键剧情对白
> NPC 自由对话
> 记忆旁白
> 系统声
```

同一时间只允许一个主声音播放。

### 11.2 抢占

- 结局独白可以停止所有较低优先级声音。
- 关键剧情对白可以淡出自由对话和旁白。
- 自由对话不能抢占关键剧情。
- 系统声不能抢占任何人物声音。
- 场景切换必须停止旧场景所有语音并清空队列。

### 11.3 字幕

- 文字先出现，语音随后开始。
- 固定剧情使用句子或短语级时间轴。
- 不做逐字高亮。
- 呼吸、停顿和表演提示保存在元数据中，不显示为字幕。
- 玩家跳到下一句时立即停止当前语音。

### 11.4 音乐与环境声

- 人物开口时 BGM 目标降低约 8 dB。
- 环境声目标降低约 3 dB。
- 对话结束后约 600 毫秒恢复。
- 关键叙事音效允许穿过对白；热点提示音不得遮挡台词。
- 所有数值最终通过浏览器实听校准，不把初始目标视为不可修改常量。

### 11.5 玩家控制

- 主音量、音乐、音效和对白音量分离。
- 支持暂停、继续、跳过、重播和全部静音。
- 设置持久化，但损坏或旧版本设置必须安全回退。
- 自动播放受浏览器策略阻止时，文字剧情仍可继续，并在首次用户交互后恢复语音能力。

## 12. AI 声线生产流程

1. 从模型内置 SFT / instruct 声线生成每个角色的三组完全合成候选；如果推理必须提供参考音频，只能使用具有生成记录的纯合成种子，不得使用真人样本。
2. 使用统一试音集比较平静、喜悦、悲伤、压抑和激动。
3. 选定声线后生成跨年龄连续性样本。
4. 锁定种子、说话人向量和档案版本。
5. 自动检查空文件、异常时长、过载、响度和文本遗漏。
6. 人工检查发音、口音、情绪、角色一致性和时代感。
7. 批准后的音频进入正式资源清单。
8. 台词、档案、模型或后处理版本变化时，只使受影响资产失效。

禁止：

- 导入任何真人语音作为参考、种子、训练或微调素材；即使拥有授权，本项目当前方案也不启用真人声音路径。
- 模仿名人、演员或普通人的可识别声音。
- 使用随机音色直接进入正式资源。
- 在未试听跨年龄样本前批准陈守义或小雨的声音血缘。

## 13. 故障处理

### 13.1 固定资产

- 资源缺失：记录错误并静音播放文字。
- 资源损坏：停止本句语音，不自动循环请求。
- 清单哈希不匹配：拒绝使用旧音频，回退静音或运行时生成。
- 音频解码失败：前端释放实例并允许下一句播放。

### 13.2 动态生成

- CosyVoice 超时：切换 Edge TTS。
- Edge TTS 超时：返回 `VOICE_UNAVAILABLE`，文字继续。
- 连续供应商失败：触发短时熔断。
- 相同台词并发请求：合并为一次生成。
- 超过文本、并发或容量限制：返回稳定错误码，不暴露内部异常。

### 13.3 错误码

```text
VOICE_PROFILE_INVALID
VOICE_LINE_INVALID
VOICE_ASSET_MISSING
VOICE_ASSET_STALE
VOICE_PROVIDER_TIMEOUT
VOICE_PROVIDER_UNAVAILABLE
VOICE_UNAVAILABLE
```

## 14. 性能与容量

- 固定剧情语音在用户触发后 200 毫秒内开始播放。
- AI 自由对白先返回文字；本地语音目标为 2.5 秒内开始第一段。
- 下一句固定对白在当前句播放期间预取。
- 生成并发、缓存文件数和总容量都必须可配置。
- 语音缓存采用最近最少使用清理，不删除当前会话正在播放的文件。
- 正式资产与临时缓存分开存储，缓存清理不得影响已审核剧情音频。

## 15. 许可证与成本边界

- CosyVoice 代码仓库和目标模型卡当前均标注 Apache License 2.0；实施前仍需锁定具体提交、权重版本和随附许可证。
- 参考：
  - https://github.com/FunAudioLLM/CosyVoice
  - https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512
- Edge TTS 只作为现有可选降级能力，不构成产品核心可用性的唯一依赖。
- 本地批量生成不产生按字符的软件费用，但未来在线实时推理仍会产生 GPU 主机、电力或运维成本。
- 产品关于页面应披露角色语音为 AI 合成，不宣称真人出演。

## 16. 可观测性

记录以下非敏感指标：

- 预生成资产命中率。
- CosyVoice 和 Edge TTS 请求量、成功率与延迟。
- 首段音频开始时间。
- 缓存命中率和缓存清理量。
- 播放、跳过、重播和解码失败次数。
- 供应商降级与静音降级次数。

不得记录：

- 用户自由输入的完整敏感内容。
- 可反推出用户身份的语音或设备信息。
- 模型密钥、内部路径和供应商原始错误响应。

## 17. 测试策略

### 17.1 内容与领域测试

- 所有 `line_id` 唯一。
- 所有声音档案、声音血缘和年龄变体可解析。
- 情绪、强度、播放策略和版本满足约束。
- 固定语音清单与台词哈希一致。
- 小雨年龄线为 22、48、87，陈守义年龄线为 25、43、77。

### 17.2 供应商与服务测试

- CosyVoice 成功、超时、空音频和异常。
- Edge TTS 降级成功与失败。
- 相同请求并发合并。
- 缓存键随文本、档案、情绪、模型和后处理版本变化。
- 熔断开启、半开和恢复。
- 失败不留下临时文件或损坏缓存。

### 17.3 前端测试

- 播放优先级和抢占。
- 场景切换清空语音。
- 文字先于动态语音显示。
- 暂停、继续、跳过、重播和静音。
- 音乐 ducking 与恢复。
- 自动播放被阻止、资源 404 和解码失败。
- 语音不可用时继续完成剧情与结局。

### 17.4 人工声音验收

- 同一人物连续生成 20 句不能明显换人。
- 陈守义三个年龄、小雨三个年龄能辨识为同一声音血缘。
- 方言不妨碍普通话玩家理解。
- 高情绪台词仍保持吐字清晰。
- 关键剧情不存在错误重音、错读人名或时代不合适的播音腔。
- 戴耳机和普通笔记本扬声器均能听清对白。

## 18. 验收标准

语音系统完成必须同时满足：

1. 固定剧情、动态对话、旁白和结局都通过统一台词模型接入。
2. 每个角色拥有版本化声音档案。
3. 陈守义和小雨的跨年龄声音连续性通过人工验收。
4. 固定剧情可离线批量生成、审核和增量更新。
5. 动态对话使用 CosyVoice，失败时自动回退 Edge TTS 或静音。
6. 字幕、音频和台词 ID 不错配。
7. 播放队列、抢占、重播和音量控制可用。
8. CosyVoice 与 Edge TTS 全部不可用时仍可通关。
9. 所有关键错误路径有自动化测试。
10. 具体模型、权重和许可证版本被锁定并记录。

## 19. 内容一致性修正

为建立小雨的声音血缘，剧情内容采用以下正式年龄线：

- 2024 年：22 岁。
- 2050 年：48 岁。
- 2089 年：87 岁。

实施时必须同步修正：

- 2089 年 NPC 年龄、身份、性格和背景。
- 2089 年系统提示和对白中“大学生”“年轻女孩”等描述。
- 2089 年人物立绘的年龄表达。
- 2050 与 2089 之间的经历和声音档案。

该修正不等于扩写完整剧情，只解决现有时间线冲突。

## 20. 后续独立项目

用户已经明确认为当前情节和核心玩法仍然偏少。语音系统定稿后，下一项工作是独立的“剧情与玩法容量扩充”设计，至少评估：

- 每个时代的主要冲突是否足够具体。
- 角色关系是否形成持续变化。
- 调查、证据、推理、选择和后果是否构成多轮循环。
- 支线、隐藏记忆和失败路径是否足以支撑重玩。
- 五个时代是否都拥有独立而不重复的玩法变化。
- 新增内容对制作、美术、语音和测试成本的影响。

该项目单独形成规格与实施计划，不在语音系统实现中顺带扩写。
