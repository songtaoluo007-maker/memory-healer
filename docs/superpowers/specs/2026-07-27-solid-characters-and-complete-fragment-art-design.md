# 拾忆 · 实体人物与全交互物美术设计

> **状态：** 已实现并通过自动化与四视口真实页面验收（2026-07-27）。
>
> **范围：** 7 张实体人物层、13 张缺失碎片特写，以及五幕交互物可见性复核。

## 1. 目标

解决当前电影舞台的两个产品问题：

1. 人物立绘通过大面积透明、横向遮罩和背景混合叠在场景上，视觉上像幽灵投影，
   缺少站在真实空间中的重量、边界和景深。
2. 17 个可收集交互物中只有 4 个拥有专属特写，玩家点击其他物件时仍回到通用
   档案图标，视觉奖励与交互重要性不一致。

本轮完成后：

- 七名可对话人物使用带透明通道的实体角色层。
- 十七个 canonical fragment ID 全部拥有独立电影特写。
- 每个交互物在对应主场景中均能被辨认。
- 人物或物品图片失败时，文字、对话、选择和继续操作仍然可用。

## 2. 已批准方向

人物采用“透明背景实体角色层”，不采用人物卡片，也不把人物永久烘焙进背景。

选择理由：

- 保留电影场景与角色切换的灵活性。
- 一个场景内可按 canonical NPC ID 显示不同人物。
- 桌面与移动端可以独立调整角色位置和景别。
- 后续替换角色或增加表情版本不需要重绘整张场景。

2089 的小雨是记忆投影，允许保留细微青紫全息边缘，但面部、服装和身体主体仍需
清晰、接近实体，不使用当前大面积半透明效果。

| 2024 | `chen_shouyi_old` | 77 岁陈守义 |
| 2050 | `xiaoyu_2050` | 48 岁小雨 |

陈守义的三张人物图继续以 1972 身份为锚点；小雨的两张图继续以 2050 身份为
锚点。站台陌生人与记者保持独立身份。

### 3.2 画面规范

- 三分之二身或接近全身，人物主体完整，手臂、肩部和头发不得被意外裁断。
- 最终运行时使用带 alpha 的 WebP；四角和人物外轮廓外必须透明。
- 禁止生成完整室内或舞台背景、文字、Logo、水印和额外人物。
- 人物默认位于画面右侧，视线指向场景或对白区域。
- 光线需匹配年代场景：1972 暖窗、1990 钨丝灯、2024 冷雨暖桌灯、
  2050 象牙典礼金、2089 青紫记忆光。
- 人物不通过降低整体饱和度来融入背景，改用环境色轮廓光和接触阴影。

透明通道是硬性验收条件。若生成结果没有有效 alpha，拒收并定向重生成；不使用
大面积 CSS `mask-image` 或低透明度掩盖不合格背景。

### 3.3 舞台呈现

`CinematicStage` 继续按 `activeNpcId` 选择人物，但角色层改为：

- 桌面主体 `opacity: 1`，无横向透明渐隐。
- 只允许脚部或最下方约 8%—12% 做轻微落地渐隐。
- 使用低强度环境轮廓光、接触阴影和局部暗边建立空间关系。
- 对话/人物观察状态显示当前人物；未选择人物时不强行显示角色。
- 因果选择出现时保留当前人物，但向右收位，不能压住选择文字和操作区。
- 手机端降低人物尺寸并移动到对白抽屉上方，不依靠降低到幽灵透明度解决遮挡。
- 2089 小雨主体不透明度不低于 0.88，只在轮廓和少量粒子处表现投影。

### 4.3 特写规范

- 4:3 横幅电影道具特写，运行时 WebP。
- 主体清楚、单一，暗边为标题与说明保留安全区。
- 与对应年代的色彩脚本一致，并保留皮影、手作磨损或记忆颗粒的统一母题。
- 信件、海报、证书、车票和时钟不得承担可读文字；准确内容由 Vue 文本表达。
- 人物情绪类碎片以手、侧脸、泪光或观众轮廓表达，避免生成新的可对话角色。
- 单张目标不超过 600 KB。

`fragmentPresentation` 从 4 个条目扩展到全部 17 个 canonical fragment ID。
未知 ID 仍返回 `null`，保留通用图标作为内容数据异常时的安全降级。

## 5. 场景内物件可见性

五张主场景逐项对照 `hotspots.json`：

- 1972：皮影戏幕、旧工具箱/刻刀、三英战吕布皮影。
- 1990：车票、皮影木箱、未寄出的信、站台时钟。
- 2024：小雨的信、泛黄剧照、最后演出海报。
- 2050：水晶奖杯、时光照片墙、全息皮影舞台、观众席泪光。
- 2089：全家福、证书档案、最后的孙悟空皮影。

优先复用已存在且可辨认的物件。只有物件缺失、被人物或 UI 完全遮挡、或与热点
位置明显不一致时，才对对应背景做局部编辑；不因本轮工作整体重生成已经合格的
主场景。

热点坐标仍由后端权威数据提供，不在前端建立第二套交互位置。

## 6. 数据与组件边界

- 后端 scene、NPC、fragment、hotspot、choice ID 和游戏规则不变。
- `ScenePresentation.portraits` 的数据结构不变，只替换为透明实体人物资产。
- `FragmentPresentation` 仍只保存图片、替代文本和焦点位置，扩展至 17 条。
- `FragmentArtwork` 继续承担单图错误边界，不把错误状态传播到剧情层。
- 人物加载失败时只隐藏人物图片；NPC 名称、对白、输入、关闭和选择继续存在。
- 主场景加载失败时继续回退 `SceneIllustration`。

## 7. 响应式与性能

- 桌面 2.39:1 舞台保留右侧人物安全区和左下字幕/选择安全区。
- 390×844、768×1024 不允许人物遮住 NPC 入口、字幕、选择或关闭按钮。
- 当前场景之外的人物和碎片不主动预加载。
- 人物单张目标不超过 800 KB，碎片单张目标不超过 600 KB。
- `prefers-reduced-motion` 下人物只即时显隐，不播放模糊、推拉或全息抖动。
- 不新增 Canvas 动画循环。

## 8. 测试与验收

自动化：

- 断言七个 NPC ID 均映射到存在且互不误用的人物资源。
- 验证人物 WebP 包含有效 alpha，而不是只有文件扩展名。
- 断言十七个 canonical fragment ID 全部具有展示映射。
- 未知 fragment 和 scene ID 保持安全降级。
- 场景、人物、碎片加载失败不影响文本和操作。
- 前端测试、类型、Lint、格式和生产构建全部通过。
- 后端 168 项测试、内容校验、Alembic 与同域烟雾保持通过。

视觉：

- 逐幕检查人物边缘、接触阴影、光向、比例和脚部落地感。
- 检查 17 个热点物件在背景中可辨认，点击后出现对应特写。
- 检查 390×844、768×1024、1440×900、1920×1080。
- 检查普通人物不再呈现大面积透明；2089 小雨仅轮廓表现投影。
- 阻断人物或碎片资源后，继续按钮、对白和剧情选择仍可操作。

1. 建立七人物实体资产与 alpha 验收测试。

5. 运行四视口视觉验收和故障降级验证。
6. 更新 CHANGELOG、TEST_REPORT 与产品路线。
