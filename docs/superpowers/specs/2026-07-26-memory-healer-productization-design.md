# 拾忆长期产品化设计规格

> 状态：已确认  
> 日期：2026-07-26  
> 首个实施范围：P0-A 产品稳定底座  
> 后续范围：P0-B 1972 电影级垂直切片、P1 五年代全面重制、P2 长期运营能力

## 1. 背景

《拾忆》当前是一个 Vue 3、TypeScript、FastAPI、SQLite 和 DeepSeek 组成的 AI 叙事游戏原型。仓库已经包含五个时代场景、七名 NPC、十七个记忆碎片、四种结局、登录存档、热区探索、蝴蝶效应、TTS、PWA 和多种视觉效果。

现有实现已积累以下结构性问题：

- 前端生产构建失败，测试套件和格式检查不能稳定通过。
- GitHub Actions 工作流无效，没有任何 job 真正执行。
- 热区、碎片关系图、场景数据和前端硬编码使用了多套不一致的 ID。
- 蝴蝶效应接口结果未写回客户端状态，关键选择无法可靠持久化。
- 1990 与 2050 的关键选择缺少完整触发路径，传承结局正常流程不可达。
- 登录密码使用无盐 SHA-256，长期令牌存储在浏览器 `localStorage`。
- README、测试报告、升级计划和实际代码进度不一致。
- UI 由大量常驻按钮、浮层和巨型组件组成，无法达到电影级产品体验。
- 现有 SVG、Canvas 和 Vue 动效分散实现，缺少可扩展的场景渲染与美术资产管线。

项目尚未正式上线，没有必须保留的真实账号、密码或存档数据，因此允许重新设计数据库和认证模型。

## 2. 产品目标

《拾忆》将从黑客松原型演进为可长期扩展、可公开运营的电影级互动叙事产品。

核心目标：

1. 游戏规则确定、可测试，不依赖 AI 是否可用。
2. 五个场景、十七个碎片、关键选择和四个结局形成真实可达的闭环。
3. 内容、状态和接口使用单一、版本化、可验证的契约。
4. 账号、会话、存档和部署达到公开产品的安全与可靠性基线。
5. 建立可复用的电影舞台、设计系统和美术资产管线。
6. 保留 DeepSeek 与 Edge TTS，同时为超时、限额和服务故障提供可玩的降级路径。
7. 本地 SQLite 与腾讯云 PostgreSQL 使用同一应用架构和迁移流程。

## 3. 非目标

P0-A 不包含以下工作：

- 不在 P0-A 内完成五个时代的最终电影级美术资产。
- 不加入 UGC、付费、社交、公会或多人功能。
- 不建立完整运营后台或无代码剧情编辑器。
- 不在修复基础闭环前扩写更多场景、NPC 或结局。
- 不为了重构而更换 Vue、FastAPI、DeepSeek 或 Edge TTS。

## 4. 里程碑分解

### 4.1 P0-A：产品稳定底座

目标是让现有五场景版本达到可构建、可测试、可部署、可完整通关的稳定基线。

交付内容：

- 修复前端类型、测试、格式和生产构建。
- 修复 GitHub Actions、Docker、Nginx、环境变量和同域 API 配置。
- 建立统一内容注册表和自动引用校验。
- 统一游戏状态结构并增加版本号。
- 修复热区、碎片、蝴蝶效应、信任度、对话历史和结局逻辑。
- 重建认证、会话、数据库迁移和用户存档模型。
- 规范 DeepSeek 与 Edge TTS 的适配、超时、重试和降级。
- 更新 README、测试报告和更新日志。

### 4.2 P0-B：1972 电影级垂直切片

目标是用 1972 西安老巷验证最终的视觉、交互和资产生产标准。

交付内容：

- Vue Router、Pinia 与 PixiJS 电影舞台。
- 全屏 2.39:1 电影构图和情境式界面。
- 4K 分层场景资产、人物半身立绘、景深、光照、雾气和水墨粒子。
- 观察、探索、对话、回忆四种情境。
- 字幕式短对话和底部半屏长对话。
- 碎片发现、记忆重组、场景进入和离开的完整镜头演出。
- 独立移动端构图和减少动态效果模式。

### 4.3 P1：五年代全面重制

目标是将 P0-B 验证过的电影系统扩展到 1990、2024、2050 和 2089，并重制结局演出。

### 4.4 P2：长期运营能力

目标是补充内容管理、分析、可观测性、备份恢复、版本迁移和腾讯云正式发布能力。

## 5. 视觉与交互设计

### 5.1 已确认的视觉方向

主视觉为“东方皮影电影感”：

- 常态画质采用动画电影写实。
- 记忆失真、碎片重组和情绪高潮采用超现实记忆电影。
- 不使用通用科幻 HUD、卡片式后台布局或传统手游常驻按钮。
- 画面、镜头和声音优先于界面；信息尽量以字幕、场记、记忆投影和场景内物件出现。

### 5.2 已确认的布局方向

主布局为“全屏电影舞台”：

- 场景始终占据主视觉。
- 常态只显示章节、记忆完整度和声音等必要状态。
- 观察、探索、对话和回忆工具按情境出现。
- 碎片、蝴蝶效应和时间线进入统一的“记忆修复台”覆盖层。
- 桌面端使用宽银幕构图；移动端使用竖屏场景和底部交互抽屉，不缩放桌面布局。

### 5.3 五年代色彩与镜头语法

- 1972：暖金、朱砂、旧木；稳定长镜头与幕布光。
- 1990：火车绿、煤烟灰、钨丝灯；横向运动和车窗流影。
- 2024：雨夜蓝、旧墙灰、深圳霓虹；更近的人物镜头和压迫构图。
- 2050：象牙白、典礼金、数字红；开阔舞台和庄重推镜。
- 2089：深墨黑、全息青、记忆紫；悬浮空间和受控的超现实重组。

## 6. 技术架构

### 6.1 前端

前端继续使用 Vue 3 和 TypeScript，并在 P0-B 正式引入：

- Vue Router：管理首页、认证、开场、游戏、存档和结局流程。
- Pinia：拆分用户会话、权威游戏状态、电影舞台和 UI 覆盖层状态。
- PixiJS：渲染分层场景、镜头、景深、光照、粒子和时代转场。
- Vue：渲染可访问的文字、表单、字幕、面板和响应式界面。

P0-A 可以先在现有组合式状态上完成正确性修复，但新增契约必须与未来 Pinia 状态边界一致，避免二次迁移。

前端模块边界：

- `api`：HTTP、会话与错误归一化。
- `stores`：用户、游戏、舞台与覆盖层状态。
- `domain`：前端纯类型、选择意图和展示模型。
- `views`：路由级页面。
- `components`：可复用 UI。
- `stage`：PixiJS 场景、镜头、图层和特效。
- `assets`：场景与人物清单，不保存游戏规则。

### 6.2 后端

后端继续使用 FastAPI、Pydantic 和 SQLAlchemy，重构为以下边界：

- `api`：请求验证、认证和响应映射。
- `application`：新游戏、进入场景、探索、对话、选择、存档和结局用例。
- `domain`：游戏状态、内容规则、碎片、信任、蝴蝶效应和结局判定。
- `content`：版本化内容注册表和引用校验。
- `integrations`：DeepSeek 与 Edge TTS。
- `persistence`：用户、会话、存档和数据库迁移。

领域层不得导入 FastAPI、SQLAlchemy、OpenAI SDK 或 Edge TTS。

### 6.3 内容单一来源

场景、NPC、碎片、热区、关键选择、转场和资产清单由后端内容注册表统一加载。

内容注册表必须验证：

- 每个场景引用的 NPC 和碎片存在。
- 每个热区引用的碎片属于正确场景。
- 每个 NPC 可透露的碎片存在。
- 每个关键选择引用的源场景、目标场景和效果字段合法。
- 每个结局条件在现有内容中可达。
- 每个场景资产清单存在必要的回退资源。

前端场景接口直接接收规范化热区和展示数据，不再维护第二套碎片 ID。

## 7. 权威游戏状态

游戏状态使用版本化结构。P0-A 的目标字段为：

```text
schema_version
game_id
revision
current_scene
visited_scenes
collected_fragments
revealed_fragments
fragment_states
npc_trust
npc_emotions
key_choices
butterfly_choices
dialogue_history
current_mood
play_time_seconds
started_at
chapter
ending
```

规则：

- `schema_version` 用于存档迁移。
- `revision` 用于防止多标签页或旧请求覆盖新存档。
- `visited_scenes` 驱动时间线和返回路径。
- `key_choices` 保存标准化选择记录；`butterfly_choices` 可以由标准化记录派生。
- 对话历史必须保存玩家与 NPC 双方消息，并受长度与摘要策略控制。
- 前端可以保存镜头和临时弹窗状态，但不得把这些字段写入权威存档。

## 8. 核心数据流

### 8.1 新游戏

1. 已认证用户请求创建游戏。
2. 后端内容注册表创建合法初始状态。
3. 后端返回状态、当前场景展示模型和内容版本。
4. 前端写入游戏 Store 并初始化电影舞台。

### 8.2 探索

1. 玩家选择后端提供的热区 ID。
2. 后端验证热区属于当前场景且满足条件。
3. 领域服务更新揭露、收集或 NPC 交互状态。
4. 后端返回状态差量和演出事件。
5. 前端根据事件播放镜头、音效和碎片演出。

### 8.3 AI 对话

1. 前端提交 NPC、玩家文本和当前游戏修订号。
2. 后端验证 NPC、场景、输入长度和速率限制。
3. 领域层构建受控的角色上下文。
4. DeepSeek 适配器请求结构化对白建议。
5. 后端验证 AI 建议中的信任、情绪和碎片效果。
6. 领域层只应用合法效果并更新双方对话历史。
7. 前端接收最终对白、状态差量和可选 TTS 地址。

AI 不得直接写入任意状态字段，也不得揭露不属于当前 NPC 的碎片。

### 8.4 选择与结局

1. 前端提交内容注册表定义的标准选择 ID。
2. 后端记录选择并计算蝴蝶效应。
3. 结局引擎根据确定性状态计算可达结局。
4. CI 中的状态机测试必须证明四个结局均存在至少一条合法路径。

### 8.5 存档

1. 后端按用户与槽位读取当前修订号。
2. 客户端提交预期修订号。
3. 修订号一致时保存并递增；不一致时返回冲突。
4. 前端提示用户加载最新存档，不静默覆盖。

## 9. 认证与数据安全

### 9.1 认证

- 密码使用 Argon2id。
- 会话令牌只保存哈希值。
- 浏览器使用 HttpOnly、SameSite=Lax Cookie。
- 生产环境在 HTTPS 下启用 Secure Cookie。
- 登录、注册和对话使用独立速率限制。
- 退出登录立即吊销当前会话。

### 9.2 数据库

- 本地默认 SQLite。
- 腾讯云生产使用 PostgreSQL。
- 数据库地址由 `DATABASE_URL` 提供。
- Alembic 管理所有表结构变更。
- 用户名和用户槽位使用数据库唯一约束。
- 存档 JSON 在写入前经过 Pydantic 模型验证。

## 10. 外部服务与降级

### 10.1 DeepSeek

- 明确的连接和总超时。
- 仅对安全的瞬时错误有限重试。
- 连续失败触发短时熔断。
- 使用 Pydantic 验证结构化响应。
- 解析失败不把原始 JSON 或元数据暴露给玩家。
- 每名 NPC 提供符合角色的本地降级对白。

### 10.2 Edge TTS

- 依赖必须锁定并进入生产镜像。
- 文本、角色、语速和音调共同生成缓存键。
- 限制文本长度、并发数、缓存文件数量和总容量。
- 缓存写入使用临时文件与原子替换。
- TTS 失败只关闭本句语音，不阻断文字对话。

## 11. 错误处理

后端统一使用机器可读错误码和用户可读消息：

```text
AUTH_REQUIRED
AUTH_INVALID
CONTENT_INVALID
GAME_REVISION_CONFLICT
SCENE_NOT_FOUND
HOTSPOT_INVALID
CHOICE_INVALID
AI_UNAVAILABLE
TTS_UNAVAILABLE
RATE_LIMITED
```

前端按错误类别处理：

- 认证错误：返回登录流程。
- 修订冲突：提示加载最新存档。
- AI/TTS 错误：使用降级对白或静音继续。
- 内容与规则错误：停止当前动作，保留上一份有效状态并记录诊断信息。
- 网络中断：允许重试幂等读取，不自动重放可能重复写入的选择或存档。

## 12. 部署与配置

- Docker 后端监听 `0.0.0.0`。
- Nginx 同域提供前端，并代理 `/api` 与 `/tts`。
- 浏览器生产环境不请求 `localhost`。
- Compose 提供开发和生产差异化配置。
- CI 使用测试环境变量，不依赖仓库中不存在的 `.env`。
- PostgreSQL、DeepSeek、Cookie 安全和允许来源均由腾讯云环境变量配置。
- 秘钥不进入镜像、日志或前端构建产物。

## 13. 测试策略

### 13.1 后端

- 内容注册表引用校验。
- 游戏状态模型和存档迁移。
- 热区探索与碎片条件。
- 信任和情绪边界。
- 蝴蝶效应记录和派生。
- 四个结局的合法可达路径。
- 注册、登录、退出、会话过期和用户存档隔离。
- 存档修订冲突。
- DeepSeek 和 TTS 的成功、超时、解析失败与降级。

### 13.2 前端

- API 客户端与 Cookie 会话行为。
- Store 的状态差量应用和修订冲突处理。
- 场景切换后热区更新。
- 玩家与 NPC 双方对话历史持久化。
- 关键选择写回。
- 电影舞台的情境切换和覆盖层互斥。
- 桌面与移动端核心流程。

### 13.3 集成与端到端

- 注册后开始新游戏。
- 完成一次探索、一次 AI 降级对话和一次存档。
- 重新登录后读取自己的存档。
- 用合法路径分别到达四个结局。
- 在 DeepSeek 和 TTS 不可用时完成基本通关。
- Docker Compose 启动后通过健康检查和浏览器冒烟流程。

## 14. CI 质量门槛

每次推送和 Pull Request 必须通过：

1. 内容引用校验。
2. Python 格式、静态检查和测试。
3. TypeScript 类型检查、ESLint、Prettier 和 Vitest。
4. 前端生产构建。
5. Docker 镜像构建。
6. Compose 集成冒烟测试。

禁止使用 `|| true` 绕过质量检查。覆盖率可以分阶段提升，但 P0-A 必须为新增和修复的领域规则提供行为测试。

## 15. P0-A 验收标准

P0-A 完成时必须同时满足：

- 后端测试、前端测试、类型检查、格式检查和生产构建全部成功。
- GitHub Actions 每个 job 正常创建并执行。
- 五个场景与十七个碎片的数据引用全部合法。
- 玩家可以通过正常操作记录关键选择与蝴蝶效应。
- 四个结局均有自动化证明的合法路径。
- 对话历史同时保存玩家和 NPC 消息。
- 注册、登录、退出、用户存档隔离和修订冲突通过集成测试。
- DeepSeek 与 Edge TTS 故障不会阻断核心流程。
- Docker Compose 可以在没有手工修改源码的情况下启动。
- 生产构建不包含指向浏览器本机 `localhost` 的 API 地址。
- README、测试报告和更新日志与实际功能、测试数量和部署步骤一致。

## 16. P0-B 性能与体验预算

P0-B 在 1972 垂直切片中遵守以下预算：

- 桌面目标画幅为 2.39:1，核心画面使用分层高分辨率资产。
- 提供 AVIF、WebP 和必要回退格式，不直接向所有设备发送 4K 源文件。
- 首个可交互场景优先加载；非关键人物表情和后续年代资产延迟加载。
- 主流桌面设备目标稳定 60 FPS，低性能和移动设备提供 30 FPS 效果档。
- 页面隐藏、减少动态效果或省电模式下暂停非必要粒子与镜头更新。
- UI 文本满足 WCAG AA 对比度；所有核心动作支持键盘与屏幕阅读器。

## 17. 决策摘要

- 产品定位：长期产品化。
- 实施原则：稳定可玩优先，然后视觉升级和新功能。
- 内容约束：允许重构剧情、结构和美术。
- 外部服务：继续使用 DeepSeek 与 Edge TTS。
- 部署目标：腾讯云。
- 分支策略：`codex/stabilize-core`。
- 技术路径：分层稳定化重构，不做最小修补或整体重写。
- 主视觉：东方皮影电影感。
- 主布局：全屏电影舞台。
- 常态画质：动画电影写实。
- 高潮画质：超现实记忆电影。
- 首个实施规格：P0-A 产品稳定底座。
